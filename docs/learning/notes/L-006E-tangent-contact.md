## 1. 本次问题

两个支撑曲线相切，是否就说明画出的线段或圆弧相切？先隔离真实内核能力，验证辅助接触点如何表达关系，再展示两个反例。

## 2. 原理与数据流

线圆相切可分解为：接触点在圆上、在直线上，圆心到接触点的半径线与直线垂直。圆圆相切可分解为：共同接触点分别在两圆上，两条半径线平行。

```mermaid
flowchart LR
    Initial[确定的初值与原生实体] --> Native[辅助接触点与真实约束]
    Native --> Contact[读取实际求解接触坐标]
    Contact --> Curves[独立验证半径与接触关系]
    Curves --> Range[检查线段参数/圆弧角范围]
```

辅助点只属于 native 实验，不冒充用户创建的持久点。输入初值不是求解结果；必须实际执行 WASM，再读参数。

原生 PT_ON_LINE 使用无限直线，PT_ON_CIRCLE 使用支撑圆的半径关系。它们不会替我们判断有限线段/圆弧范围。Native 返回码 4 是允许冗余的成功，不能误判失败，也不能据此忽略范围检查。

## 3. 最小实验

```powershell
. ./scripts/use-node.ps1
npm run check:tangent-primitives
```

环境：Windows x64、PowerShell7.6、Node24.21.0、npm11.19.0；既有自建WASM，未重建。使用原生二维基准面，尚未接规范领域草图、Worker 或 UI。

输入：半径10的圆与水平线y=8；半径10/8的两圆，第二圆心x初值19（外切）或3（内切）；半径10第一象限弧与半径8的圆。半径固定，圆心/线位置和接触点由真实求解调整。

负向输入：线段 (-20,10)—(-15,10)；圆弧从 (0,10) 到 (-10,0) 逆时针。两者的支撑曲线允许接触点 (0,10) 或 (10,0)，但有限范围排除该点。长度/位置断言容差1e-5mm；范围按实际参数判断。

## 4. 实际结果与证据

| 输入 | 期望 | 实际 | 证据 |
| --- | --- | --- | --- |
| 线圆 | 线移至y=10，接触点(0,10) | 通过；真实DOF1 | [原生记录](../evidence/T-201B1-tangent-primitives.json) |
| 圆圆外切/内切 | 圆心距18/2，接触点(10,0) | 通过；DOF0 | 同上 |
| 弧圆 | 接触在弧端点(10,0) | 冗余成功码4、DOF0 | 同上 |
| 延长线/弧外反例 | Native可接受，但领域须拒绝 | 线参数t=4；弧偏移3π/2大于弧跨度π/2 | 同上 |

六组实际执行，无native错误。早期弧实验误加一个未连接的半径参数，使DOF多1；最终脚本只为圆创建半径参数，弧圆DOF为0。实验没有随机或合成输出。
