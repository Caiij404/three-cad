## 1. 本次问题

草图保存二维坐标，但视口和实体计算需要世界坐标。怎样让相同的二维矩形在三个平面中都有明确方向和可验证的往返？

## 2. 原理与数据流

平面用原点 origin、水平基向量 u、竖直基向量 v 表示，基向量单位且相互正交。映射为 `world = origin + u*x + v*y`，法线为 `u×v`；反投影先减 origin，再分别点乘 u、v。

| 平面 | u / v | 法线 | (40,30) 的世界位置 |
| --- | --- | --- | --- |
| XY | X / Y | +Z | (40,30,0) mm |
| XZ | X / Z | -Y | (40,0,30) mm |
| YZ | Y / Z | +X | (0,40,30) mm |

XZ 的法线是 -Y，这是右手系叉积的结果。后续负深度沿法线反向，不能凭平面名称猜方向。反投影还要检查法线方向距离，离面点不能被静默压平。

## 3. 最小实验

纯函数在 [plane.ts](../../../src/core/geometry/plane.ts)，不依赖 Three 或 DOM。

```text
输入：三基准面各测试 (0,0)、(40,30)、(-9999.123456789,0.000001)、(9999.0001,-123.456789)。
操作：toWorld 后 toPlane；另测平移旋转基向量、离面 0.01 mm、非法基和 Infinity。
命令：. ./scripts/use-node.ps1；npm run check:plane
环境：Windows x64 / Node 24.21.0；标准 JS Number double。
期望：三法线与 PRD 一致；往返误差 ≤1e-6 mm；非法输入明确拒绝。
容差：单位正交检查 1e-8；平面距离与往返 1e-6 mm。
```

## 4. 实际结果与证据

12 个基准面输入的往返误差均为 0，世界位置和法线精确匹配预期。[JSON](../evidence/T-103-plane.json) 逐项保留输入、frame、world、返回值和容差；[日志](../evidence/T-103-plane.log) 记录 2 个测试通过。

平移原点 (50,-20,10)，u=(√½,√½,0)，v=(0,0,1) 的测试往返也在 1e-6 mm 内。离面、非正交基与非有限输入均拒绝。没有把 Float32 显示位置作为数学结果。

## 5. 接回项目

空草图持有可序列化 PlaneFrame，Three 适配层通过 toWorld 构建显示，进入草图相机用 normal 和 v 定向。三入口已实际创建/进入/退出/再次编辑 XY、XZ、YZ 空草图，ID 保留。

AC-003-1 的 double 坐标前置已证明；完整实体绘制/预览清理/约束保持需要 T-104/T-201 的非空草图验收。任意平面仍属 P1，本次旋转基夹具只验证通用数学函数。
