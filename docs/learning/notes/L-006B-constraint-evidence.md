## 1. 本次问题

求解器说“成功”，是否足以证明草图满足要求？本篇从输出坐标独立计算残差，再读取原生状态和自由度，区分成功、欠约束和冲突。

## 2. 原理与数据流

点是未知坐标，约束是需要满足的关系。固定 `p0` 消除整体平移；水平/垂直关系控制方向，宽高控制尺寸。求解器调整初始猜测，使关系成立。

长度残差是 `abs(实际长度 - 目标长度)`；水平残差是两端 y 差的绝对值。圆弧切线与半径垂直，本夹具用单位半径向量与单位切线向量的点积绝对值检查，目标为 0。

DOF 是求解器返回的剩余自由度，不由点数猜测。冲突时返回原生 `bad` 映射出的约束 ID；不接受失败坐标作为可提交几何。

## 3. 最小实验

输入、约束、初始猜测和独立检查全部在 [solver-fixtures.ts](../../../src/experiments/solver-fixtures.ts)。矩形初始点刻意偏斜；圆弧终点为 `(0.5,8)`，而非把目标 `(0,10)` 直接填作答案。

```powershell
. ./scripts/use-node.ps1
npm.cmd run check:solver
npm.cmd run check:solver:browser
```

环境与二进制见 [L-006A](L-006A-wasm-worker.md)。长度/坐标容差 `1e-5 mm`；本次相切归一化点积容差 `1e-5`（它是无量纲检查，并非全角度约束的验收）。

## 4. 实际结果与证据

| 输入 / 操作 | 期望 | 实际 | 判定 |
| --- | --- | --- | --- |
| 矩形宽 40→60，高 30 mm | 各尺寸满足；DOF 0 | 两次宽高残差均 0；DOF 0 | 通过 |
| 宽 40.123456789、9999.0001 mm | 小数细节保留 | 两项尺寸残差 0；DOF 0 | 通过 |
| 同一宽加 40 与 50 | inconsistent，不输出候选坐标 | 冲突 ID 为 width/conflicting-width；points=null，输入不变 | 通过 |
| 删除宽约束 | under-constrained | 原生 DOF=1 | 通过 |
| 半径 10，水平切线长 20 mm | 半径、长度和相切满足；DOF 0 | 圆弧终点 `(0,10)`；长度/半径/水平/点积残差均 0 | 通过 |
| 交替矩形重复求解 | 前一模型不污染后续模型 | Node 两批合计 60 次；各 Worker 30 次，尺寸稳定 | 通过 |

全部输出坐标、冲突集合及残差见 [Node 证据](../evidence/T-003-solver-node.json) 和 [浏览器证据](../evidence/T-003-solver-browser.json)。8 项是夹具检查数量，不代表 8 条完整需求通过。

另有 5 项非法输入：NaN、缺失引用、零长线、错误约束对象和重复 ID，均在进入原生 API 前被明确拒绝。数值检查来自真实 C++ 结果，未使用随机坐标或模拟求解器。
