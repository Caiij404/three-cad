# 技术决策记录

更新：2026-10-02。M0 gate 已通过；指定内核/几何/Worker/路径/恢复有真实证据，进入 M1，完整需求未验收。

## ADR-001：以 Vue 3 替换 React

**决策：** Vue 3 SFC + Composition API + TypeScript，Pinia 管理 UI 状态和领域快照；Vite 构建。

**依据：** 上游 package.json 使用 React/React DOM、Redux/react-redux；Three.js 本身不要求 React。但 Scene.js 接收 store，并通过 subscribe/getState 与 Redux 连接，直接访问 DOM 和 window 全局。

**迁移边界：**

| 上游职责 | 新项目实现 |
| --- | --- |
| React JSX、组件生命周期、工具栏 | Vue SFC、onMounted/onUnmounted、composables |
| Redux 选择/模式/树状态 | Pinia + 领域命令服务 |
| Scene 的 Redux 回调和全局对象 | 显式 ViewportRuntime 接口，选择事件输出 ID |
| Three.js 绘制、拾取、空间变换 | 视口适配层；按所锁定版本重写或适配 |
| WASM 求解和实体操作 | Worker + solver/solid adapter |
| Webpack 与旧 Babel/Tailwind 配置 | Vite + TypeScript；首期使用普通 CSS |

不能通过 npm 卸载 React、安装 Vue 就完成迁移。复用范围由 M0 确定，不预设所有上游 JS 都可直接搬迁。

**响应式规则：** 领域数据可以响应式；renderer、scene、mesh、WASM 模块不深度代理。必要时用 shallowRef/markRaw；运行时实例由组件外专用对象持有并销毁。

## ADR-002：首期使用网格 CSG 路线

**决策：** 保留 three.cad 的草图求解、拉伸、网格布尔路线。SolveSpace WASM 负责二维约束，Three.js 负责展示/预览，CSG 负责布尔。

**原因：** 这是用户选定的项目方向，先实现对应闭环。引入 OpenCascade 会改变实体表达、选择拓扑、导出和构建成本，不属于简单替换 React。

**限制：** 圆弧/圆需要细分；布尔可能遇到共面、相切、薄片失败；MVP 仅 STL，不承诺 STEP 或工业精度。

**验证要求：** M0 以 THREE-CSGMesh 路线作为首选，测量所选版本与 Three.js 兼容性。失败时评估其他网格 CSG 库并记录替代证据；不得静默改成 BREP 或删除约束功能。

## ADR-003：领域数据与显示分离

**决策：** 纯 TS core 存草图、约束、特征和依赖；网格为可再生缓存。Vue/Pinia/Three.js/SolveSpace 指针均不能成为文件格式。

**原因：** 重算、撤销、保存和迁移需要稳定数据。上游对象序列化方式作为参考，不作为新文件兼容契约。

**代价：** 需要显式类型、适配器、事务和依赖图；避免 UI、GPU 对象和求解器对象互相持有。

## ADR-004：Worker 与原子事务

**决策：** 求解和布尔运行于 Worker。请求包含 session、requestId、revision；候选文档全链重算成功才提交。

**原因：** 约束拖动和 CSG 可能耗时，且异步结果会乱序。失败时保留旧有效项目比提交半个特征图更可预测。

**取舍：** MVP 对失败上游修改整体回滚，而不是提交一个含失败后代的文档。UI 提供具体失败原因，未来可增加显式失效特征模式。

## ADR-005：新目录与分阶段交付

**决策：** 项目名 three-cad-vue，路径 `D:\Fighting\Learn\three-cad-vue`。初次交付只创建立项文档；后续实现从 M0 起。

**原因：** 用户要求先立项并写 AI agent 可执行的需求。先消除内核/版本风险，再建设完整 UI。

## ADR-006：复用与第三方来源

上游仓库提供 GPL-3.0 LICENSE，这是已核对的仓库事实。本轮没有复制其代码，也没有把新项目标注为 MIT。

M0 应为计划复用的源码、WASM 和第三方库建立清单，记录来源 URL、固定 SHA/版本、许可证、改动及构建方法；复用上游文件时保留对应声明。项目最终 LICENSE 在复用清单确定后设置，不在立项阶段猜测第三方授权。

## ADR-008：从固定 SolveSpace 源码重建，不采用旧求解器分发文件

**原决策：** SolveSpace WASM 路线确定，是否直接使用 three.cad 的 WASM 与包装器待 M0 验证。

**证据：** T-001 固定四个仓库与 33 个文件指纹；旧静态库未找到完整源码/工具/参数链。旧包装器使用 float/Float32，未回传 result/dof；独立转换实验中 9999.0001 mm 的误差约 1e-4 mm，超过 PRD 的 1e-5 mm 目标。此实验未执行求解器。

**决策：** 不把旧 dist/solver.* 或 libslvs.a 当作应用输入。采用固定官方 SolveSpace 源码的 slvs-wasm 目标作为重建候选，保留许可证与依赖指纹；登记数组索引补丁，实际构建、精度、错误、DOF 与 Worker 行为在 T-003 验证。CSG 从固定 THREE-CSGMesh 原库选取候选路径，兼容性在 T-004 验证。

**影响：** 保持 SolveSpace + 网格 CSG 路线、领域数据和 P0 范围。新增可追踪构建工作，没有把源码审计判作 M0 gate 通过。详见 [UPSTREAM](UPSTREAM.md)。

## ADR-009：锁定实际兼容的最小工具链

**原决策：** Vue SFC + TypeScript + Vite 已确定，但版本、运行命令与兼容性未实测。

**证据：** 全局 Node `20.11.1` 不满足 Vite 8 的 `20.19+ / 22.12+` 要求。首次组合 TypeScript `7.0.2` + vue-tsc `3.3.11` 在类型检查时报 `ERR_PACKAGE_PATH_NOT_EXPORTED`，入口为 `typescript/lib/tsc`；安装成功和 peer 范围 `>=5.0.0` 不足以证明实际兼容。

**决策：** 锁定 Node `24.21.0`、npm `11.19.0`、Vue `3.5.43`、Vite `8.3.2`、plugin-vue `6.0.9`、TypeScript `6.0.3`、vue-tsc `3.3.11`、@types/node `24.19.0`、Playwright `1.63.0`。提交锁文件；Windows 使用校验归档的项目内便携 Node，保持全局安装不变。

**验证：** `npm ci` 后类型检查与生产构建通过；Edge 开发/生产页面真实加载和交互通过。独立错误 SFC 在 vue-tsc 中报 TS2345、单独 Vite 构建退出 0，因此主工程的 `build` 必须先做类型检查。证据见 [VERIFICATION](VERIFICATION.md)。

**影响：** T-002 只建立最小验证页，暂不安装 Pinia、Three.js 或几何内核；不改变需求、领域数据格式或 M0 gate。真实 WASM 的 Worker 与 `/cad/` 路径继续由 T-003 验证。

## ADR-011：真实构建的独立 ESM/WASM 与局部验证边界

**原决策：** ADR-008 选择官方源码重建，尚未实际编译。

**实测：** SolveSpace `2879a02d`、固定 Eigen/mimalloc、Emscripten 4.0.8 编译成功；真实矩形与圆弧相切、冲突、原生 DOF、开发/生产/子路径 Worker 均通过。32 MiB 初始缓冲区首次求解增长至 40304640 bytes，热身后同负载稳定。Windows worktree 的绝对 gitdir 暴露 CMake 路径错误；三个补丁随产物登记。

**决策：** 使用独立 `slvs.mjs` / `slvs.wasm`，ESM 工厂在 Worker 加载，保留双精度并复制结果后清空原生模型。初始内存改为 32 MiB，允许增长；导出 HEAPU8 仅用于实际内存观测。明确资源加载错误与重试，限定 Vite HTML 扫描入口。

**影响：** 引入真实 GPL-3.0-or-later SolveSpace，设置项目 LICENSE 并保留依赖及编译运行时的原许可。领域格式不保存 handle。此次不是完整 P0 约束、事务和 M0 gate 验收，CSG 继续实测。详见 [构建清单](third-party/solver-build.json) 与 [验证](VERIFICATION.md)。

**执行节奏：** 用户随后授权连续推进至会话预算耗尽；继续按任务依赖和每任务一个 commit，不等待可选学习反馈，不代填用户掌握状态。

## ADR-012：原始 BSP 核心与一致边界三角化

**原决策：** THREE-CSGMesh 为首选候选，旧 Three.js 桥接尚未验证。

**证据：** 固定 `8bd00fe9` 的 `csg-lib.js` 可与 Three.js 0.186.1 连接；旧桥接含 Float32 输出与自动 Worker 导入。原始重叠方块 union 体积 12000 正确，但 12 条边未配对，不能作为可导出的闭合实体。

**决策：** 只保留未改动 BSP 核心，编写 TypeScript bridge；将已有顶点对齐到相邻多边形边界后，从中心三角化。保留 Number 坐标、检查二流形边和顶点 link、方向/体积。边/顶点接触 union 明确拒绝；空结果显式零三角形。桥接扫描暂限 2000 顶点，暂不承诺复杂模型效率。

**影响：** 路线仍是网格 CSG，没有改成 BREP。M0 19 项几何、16 个 STL 解析与三入口 Worker 通过；通用轮廓、曲线、完整导出/布尔 UI 继续后续任务。Three/Earcut/CSG 原声明随分发保留，项目 GPL 许可不改动。

**来源字节修正：** T-003 最终缓存检查曾提示原始上游空白，Git 自动行尾会改变生成 mjs 的 SHA。T-004 为这些精确来源路径设置 `-text` / 原始空白例外，直接验证 Git index 与构建清单指纹一致；只调整原始文件，不放宽自写源码检查，保留已推送历史。

## ADR-015：候选文档、运行时校验与原子历史

**证据：** T-102 的 15 项测试覆盖 JSON/引用/DAG、缓存与文档整体撤销、失败回滚、晚到事务和 100 步历史。真实 CSG 固定矩形深度 20→30→undo→redo，体积 8000→12000→8000→12000 mm³；三个浏览器入口的项目元数据操作通过。

**决策：** core 持有普通领域文档、数字缓存和命令历史，几何命令必须提供真实重算入口。候选在提交前后通过字段白名单、有限数值、稳定 ID/定义与闭合网格检查。app/ProjectSession 持有权威 engine，Pinia 只接收普通快照；视图卸载不销毁文档。dirty 按成功保存快照指纹计算，保存 UI 未实现时保持禁用。

**影响：** schema 按 PRD 限定两点 distance、角度 `(0, π)` radians、深度绝对值至少 0.01 mm；不扩大需求。测试的固定矩形桥接仅作事务隔离，不宣称通用轮廓/拉伸/后代重算通过。原始 M0/T-101 证据保留，重放独立存档。下一任务 T-103，用户复述仍未记录。

## ADR-016：独立视口所有权与空草图生命周期

**证据：** T-103 的 double 三平面往返、真实 WebGL2 四类拾取/实体夹具、鼠标/模式/隐藏/resize、context 扩展恢复、20 次资源与实际 UI 新建通过；开发/root/cad 三入口无非预期错误。实际驱动是 RTX 4070 Ti / ANGLE D3D11。

**决策：** Three 运行时独立持有 canvas、资源、Controls、监听、ResizeObserver 与 RAF；Vue 用 shallowRef/markRaw，Pinia 仅存 ID/普通快照。拾取按 canvas CSS rect 计算 NDC，近平行平面填充不参与拾取。默认 Z-up，草图沿 normal 正视、v 为上方，退出恢复模型相机。新建会话重置视口；context lost 保留文档，restored 重建显示与拾取。

**影响：** 空草图没有方程/实体缓存，其事务采用明确的空输入恒等回调，非空输入仍拒绝；不假报求解成功。绘制等待 T-104 真实管线。当前相机在运行时保存，文件相机同步等待 T-401。资源计数只证明小夹具/新建；文件打开、长期堆与复杂模型未验收。正常生产包约 688 kB 的 chunk 提示保留并记录，性能任务后续处理。用户复述未记录。

## ADR-017：T-104 分步交付与领域求解前置

**证据：** 现有M0协议不能直接描述规范领域圆/方向圆弧/coincident。T-104A 新adapter在未改变WASM产物的情况下，12项领域fixture、4项拒绝、三入口专用Worker及真实事务通过；原M0和领域/协议/工程/项目回归通过。

**决策：** T-104拆为A真实领域求解、B绘制/捕捉、C拖动/删除/完整回归，每个子任务一个commit，整体条件不变。领域ID与native handle只在adapter内映射；圆半径使用独立native参数，clockwise交换native首尾。先校验支持子集，成功后独立检查残差；失败返回无候选。app拥有DocumentSolverClient，原M0 Worker保持独立。
